## M1-1（一般）返回数组长度与填充长度不是同一个数 —— **已修**

`llama_jni.cpp` nativeEmbed 末段：

```cpp
jfloatArray out = env->NewFloatArray(nEmbdOut);   // 长度 = n_embd_out
if (!out) return nullptr;
env->SetFloatArrayRegion(out, 0, nEmbd, vec.data());  // 只填 n_embd 个
return out;
```

- **现象**：`n_embd_out > n_embd` 时返回数组尾部是**补零**，而调用方
  （`LlmEngine.buildIndex` 用 `v.size != dim` 判、`EmbeddingsApi` 用
  `vec.isEmpty()` 判）拿到的长度是 `n_embd_out`，两个数不同口径。
- **当前为什么没爆**：上面 `output_dim_ok(nEmbd, nEmbdOut)` 要求**严格相等**，
  不等就 `return nullptr`，于是走不到末段。**这道闸是唯一的东西在挡它。**
- **为什么仍要修**：闸挡的是"值不相等"，没挡"长度与填充数不必相等"。
  哪天 `output_dim_ok` 放宽成 `>=`（那正是"输出维度更长时语义被截掉一截"那条注释
  在讨论的方向），这里会**静默**返回一段带零尾的向量 —— 归一化后方向偏离，
  检索命中率凭空下降，接口 200。
- **修法（已落）**：`NewFloatArray(nEmbd)` —— 两个数**只写一个**，
  不再各写一个数。判据落在 `tools/embed_robust/check_return_contract.py`
  （锚的是"分配实参与填充实参是**同一个标识符**"，不是"出现过 nEmbd"），
  桩㊵/㊶ 已验证它在该红时红（退回 `nEmbdOut` / 填充起点不为 0）。

### 这一轮最该记住的一条

前两轮的教训是"读守卫的**结论**、没读**判据**"。这一轮没再犯那个 ——
但它露出了**同一族的第三张脸**：我读的是**数据流上的判定函数**
（`rank` / `select` / `render` / 三态出口 / 信封 / 行数口径），
却漏了**落盘前的最后一米**（三处 `substring` + 一处 UI 行号构造）。
而恰恰是那一米，把内存里"看着对"的东西写成磁盘上"已经烂掉"的东西。

所以规矩补一条：**逐行走查要按「落盘出口」数，不只按「判定函数」数。**
一个值从内存到磁盘，每一次 `substring` / `toByteArray` / `put` 都是一站。
